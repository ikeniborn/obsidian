# Setup

Interactive configuration performed by `setup.sh`. It produces `/opt/notes/.env`, selecting the sync backend, domain/email, TURN credentials, S3 backup settings, and a backup scheduler, plus optional Docker proxy/DNS fixes. Runs after [[installation#Dependency Installation]].

## Environment Generation

`setup.sh` is the second deployment stage. It writes the single source of secrets, `/opt/notes/.env`, consumed by `deploy.sh` and the compose files. It requires `/opt/notes` (created by [[installation#Directory Structure]]) and aborts via `check_notes_directory()` if missing.

The `main()` flow (lines 1360-1512) runs: directory check, existing-`.env` check, optional Docker proxy config, network selection, nginx selection, domain prompt, certbot-email prompt, backend selection, conditional backend config, S3 prompt, validation, DNS test, `create_env_file`, summary, then scheduler choice. `check_existing_env()` (lines 83-98) detects an existing `.env`, prompts to overwrite, and on confirmation backs it up to `.env.backup.<timestamp>` before regenerating.

`create_env_file()` (lines 892-1128) assembles the file in sections via heredocs: CouchDB credentials, domain, SSL (`CERTBOT_EMAIL`, `CERTBOT_STAGING=false`), data dirs, network config (mode/name/external/subnet), nginx config, then conditional S3, backend, CouchDB, and ServerPeer blocks. The file is finalized with `chmod 600`. Network mode/name come from `scripts/network-manager.sh`, and nginx container selection from `scripts/nginx-setup.sh`. See [[architecture#Configuration & Secrets]].

## Backend Selection

`prompt_sync_backend()` (lines 608-672) offers three choices: `1) CouchDB only`, `2) ServerPeer only`, `3) Both`, defaulting to CouchDB. The choice sets `SYNC_BACKEND` (`couchdb`/`serverpeer`/`both`) and drives every downstream conditional in the script.

The selection also sets the S3 prefix defaults and nginx location paths. CouchDB-only sets `S3_BACKUP_PREFIX=couchdb-backups/` and `COUCHDB_LOCATION=/`. ServerPeer-only sets `serverpeer-backups/` and `SERVERPEER_LOCATION=/`. Both-mode sets distinct prefixes (`COUCHDB_S3_BACKUP_PREFIX`, `SERVERPEER_S3_BACKUP_PREFIX`) and prompts interactively for separate URL location paths (defaults `/couchdb` and `/serverpeer`).

Crucially, backend-specific variables are only written to `.env` when their backend is selected (`create_env_file`, lines 1048-1123): the CouchDB block (`COUCHDB_CONTAINER_NAME`, `COUCHDB_PORT=5984`, `COUCHDB_LOCATION`) is emitted only for `couchdb`/`both`; the ServerPeer block (vault config, TURN vars, Nostr relay) only for `serverpeer`/`both`. `configure_couchdb()` (lines 599-606) prompts the CouchDB container name (default `notes-couchdb`); `configure_serverpeer()` (lines 674-786) handles multi-vault ServerPeer setup. See [[couchdb-backend#Container Definition]].

## Domain & Email

`prompt_notes_domain()` (lines 493-521) reads `NOTES_DOMAIN`, validating against a basic domain regex; empty input defaults to `notes.localhost` (development mode). `prompt_certbot_email()` (lines 468-491) loops until a regex-valid email is entered, storing it as `CERTBOT_EMAIL` for Let's Encrypt notifications.

Both values are required by `validate_config()` (lines 359-393), which errors if either is empty. After validation, `test_dns_resolution()` (lines 395-437) checks that `NOTES_DOMAIN` resolves (skipping `notes.localhost`), trying `host`/`dig`/`nslookup`; on failure it warns and prompts to continue, and warns if the resolved IP differs from the local `hostname -I` address. Both land in `.env` as `NOTES_DOMAIN` and `CERTBOT_EMAIL`, consumed by SSL setup during [[deployment#Deployment Orchestration]].

## TURN Configuration

TURN/STUN credentials are generated by `configure_serverpeer()` (lines 753-786), invoked only when the backend is `serverpeer` or `both`. It detects the server public IP via `curl -s ifconfig.me` (falling back to `icanhazip.com`, then a manual prompt) into `EXTERNAL_IP`.

Credentials are fixed username `obsidian` plus a random `TURN_PASSWORD=$(openssl rand -hex 16)`, with `TURN_REALM=turn.<domain>`. It writes `SERVERPEER_STUN_SERVERS=stun:stun.l.google.com:19302` (Google public STUN) and `SERVERPEER_TURN_SERVERS=turn:obsidian:<pass>@<ip>:3478` (local coturn), plus `COTURN_LISTENING_PORT=3478` and `COTURN_EXTERNAL_IP`. ServerPeer reaches the Nostr relay internally over `ws://notes-nostr-relay:7000`.

`configure_turn_firewall()` (lines 788-828) opens the TURN ports in UFW (again only for serverpeer/both): `ufw allow 3478/udp`, `3478/tcp` (signaling), and `49152:65535/udp` (relay). It returns early if UFW is missing (printing manual commands) or if the ports are already present. These vars feed `coturn-setup.sh` during deploy. See [[turn-stun-p2p#Credential Generation]] and [[firewall-security#UFW Configuration]].

## S3 Backup Configuration

`prompt_s3_credentials()` (lines 830-890) optionally configures S3-compatible backup storage (AWS S3, Yandex Object Storage, MinIO). Pressing Enter at the access-key prompt skips S3 entirely, leaving backups local-only. If an access key is supplied, secret key and bucket name are mandatory (skipping the rest if blank).

Endpoint defaults to `https://storage.yandexcloud.net` and region to `ru-central1`. The backup prefix handling is backend-aware: in `both` mode it shows the dual prefixes (`COUCHDB_S3_BACKUP_PREFIX`, `SERVERPEER_S3_BACKUP_PREFIX`) and offers to customize each; single-backend mode prompts for one `S3_BACKUP_PREFIX` defaulting to the backend value set in [[setup#Backend Selection]].

`create_env_file()` only writes the S3 section (`S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_BUCKET_NAME`, `S3_ENDPOINT_URL`, `S3_REGION` plus prefix(es)) when `S3_ACCESS_KEY_ID` is non-empty (lines 1004-1036). These credentials are read by the backup scripts and `s3_upload.py`. See [[backup-system#S3 Upload]].

## Backup Scheduling

After writing `.env`, `main()` prompts for a backup scheduler (lines 1404-1415): `1) Cron` (default) or `2) Systemd timer`. The chosen mechanism schedules the backend-appropriate backup script(s) plus a standalone disk-cleanup job, all logging to `/opt/notes/logs/backup.log`.

`setup_backup_cron()` (lines 1130-1188) first strips any existing `couchdb-backup.sh`/`serverpeer-backup.sh`/`cleanup-system.sh` crontab lines, then installs backend-aware jobs: CouchDB-only at `0 3` (3:00 AM), ServerPeer-only at `0 3`, and in `both` mode two jobs — CouchDB at 3:00 and ServerPeer at `5 3` (3:05 AM). It always adds a `cleanup-system.sh` job at `30 3` (3:30 AM).

`setup_systemd_timer()` (lines 1190-1228) is the modern alternative: it generates `<backend>-backup.service`/`.timer` unit files (`OnCalendar=*-*-* 03:00:00`, `Persistent=true`) via `setup_systemd_timer_for_backend()`, creating two timers in `both` mode. It also calls `setup_cleanup_systemd_timer()` to install `notes-cleanup.timer` at 03:30, and removes legacy unit files (old `couchdb.timer`/`serverpeer.timer`) for forward compatibility. See [[backup-system#Systemd Timers]].

## Docker Proxy Setup

`configure_docker_proxy()` (lines 221-341) is an optional first step in `main()`, intended for restricted networks where Docker Hub is blocked. It prompts `Configure Docker proxy? (y/N)`, requires root (offering to continue without proxy if not), and validates the proxy URL begins with `http://`, `https://`, or `socks5://`.

On confirmation it writes `/etc/systemd/system/docker.service.d/http-proxy.conf` with `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY` (default `localhost,127.0.0.1,::1,docker-registry.local`), runs `systemctl daemon-reload`, restarts Docker, and verifies the proxy via `docker pull hello-world`. See [[networking#Docker Proxy]].

If the test pull fails, it warns about DNS hijacking and offers `fix_docker_hub_dns()` (lines 132-219), which resolves the real Docker Hub IPs using `resolve_dns()` (lines 100-130, trying dig/nslookup/host/getent against 8.8.8.8), falling back to known-good IPs (verified 2025-01-29) if all methods fail. It backs up and edits `/etc/hosts` to pin `registry-1.docker.io`, `auth.docker.io`, and `production.cloudflare.docker.com`, bypassing the hijack. See [[networking#DNS Hijacking Fix]].
