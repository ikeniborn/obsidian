# Бэкенды синхронизации

Obsidian Sync Server поддерживает два независимых бэкенда синхронизации, выбираемых при конфигурации. Возможно использование обоих одновременно (режим `Both`).

## Сравнение бэкендов

| Параметр | CouchDB | ServerPeer |
|----------|---------|-----------|
| Архитектура | Клиент-Сервер | P2P (WebSocket + WebRTC) |
| Протокол | HTTP REST | WebSocket (WSS) + WebRTC |
| Хранилище | База данных (CouchDB 3.3) | Файловый vault (filesystem) |
| Порт | 5984 (localhost) | 3000 (localhost) |
| Имя контейнера | `notes-couchdb` | `notes-serverpeer` |
| Runtime | Docker (official image) | Deno (самосборный контейнер) |
| Backup-скрипт | `couchdb-backup.sh` | `serverpeer-backup.sh` |
| Зависимость от хоста | Нет | Нет (Deno, Node.js, git — в контейнере) |
| Offline-capable | Нет | Да |

## Общие (backend-independent) возможности

- S3-резервное копирование (общий `s3_upload.py`)
- Nginx reverse proxy (шаблоны учитывают бэкенд)
- UFW firewall
- SSL/TLS (Let's Encrypt)
- Health checks и мониторинг
- Cron/systemd резервное копирование

## Выбор бэкенда

Производится в `setup.sh` интерактивно. Определяет:
- Какие переменные добавляются в `/opt/notes/.env`
- Какие systemd timer-ы создаются
- Какие UFW-правила применяются (TURN-порты только для ServerPeer)
- Какой шаблон Nginx используется

## S3-префиксы при режиме Both

При использовании обоих бэкендов используются раздельные S3-префиксы:
```bash
COUCHDB_S3_BACKUP_PREFIX=couchdb-backups/
SERVERPEER_S3_BACKUP_PREFIX=serverpeer-backups/
```
